# Coverage matrix

Four attack cases and eleven edge cases, each mapped to the code that addresses it, the tests that prove it, the demo scene that shows it, and how it can still fail. Built on 6 Nov 2026 and checked against the code again on 7 Nov 2026 by reading the source and test files; the tests were not run for this page.

## Legend

1. Mechanism: what in Cordon addresses the case, with file paths.
2. Proof: test names quoted verbatim, then the file. Only tests that assert the claim are listed.
3. Demo: a beat in [docs/demo.md](demo.md) by its time, or a `pass` line in [ops/e2eLocal.sh](../ops/e2eLocal.sh) by its line number. None means neither shows it.
4. Status:
   1. handled: code exists and tests assert the claim.
   2. partly handled: tests assert part of the claim, or Cordon covers the case only after a delay or only with advice.
   3. not handled: Cordon has nothing for the case.
   4. not proven: code or design claims to cover it, but no test asserts it.
5. Known bypass: a concrete way the case still gets through.

Two facts shape several rows. sandboxCanary runs only on demo registry tarballs, so a real public version can collect at most two votes (staticScripts and advisoryFeed), and the demo quorum of 2 needs both. The suggested MAX_SEALS_PER_DAY is 10 ([docs/open_decisions.md](open_decisions.md)).

Three more facts. A version with live votes below quorum is Suspect (status None with a live vote, contracts/src/SealRegistry.sol `isSuspect`), and `cordon check` and `cordon install` block it by default; `--allow-suspect name@version` lets one version through and the sidecar only warns (packages/guard/src/cli.ts, check.ts, sidecar.ts). Votes expire after VOTE_LIFETIME_SECONDS, an immutable set at deploy (86400 in ops/e2eLocal.sh). Nothing is deployed to a public testnet: SealRegistry waits on funding, the Arkiv writer is unfunded so no evidence entity exists yet, and the Chainlink CRE workflow (cre/cordonAdvisory) runs only as a local dry run simulation.

## Not proven

1. Valid provenance on a malicious release. Add a test that feeds staticScripts or the guard a version with valid provenance metadata and asserts the verdict and outcome are unchanged, or a fitness test that fails if any guard or detector source reads provenance or attestation fields.

Claims inside other rows that still lack a test:

1. Privacy: no test asserts that the chain requests carry no package name.
2. Deep transitive: no lockfile fixture nests deeper than two levels.
3. Wiper fallback: "real Docker run flags 1.4.1 and passes 1.4.0" in services/detectors/src/sandboxCanary.test.ts runs only with CORDON_DOCKER_TESTS=1.
