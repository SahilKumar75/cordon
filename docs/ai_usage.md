# AI usage

ETHGlobal asks every team to document where and how AI tools were used. We used Claude Code (model Claude Opus 5.5) as an orchestrator with one subagent per area. Every prompt the team gave is in docs/prompts, and every agent definition is in .claude/agents. Team decisions are recorded by hand in docs/decisions.md, which no agent edits.

## Team

1. First idea (Sluice, a research integrity oracle): product rules, stack, phases and style rules written by the team (docs/prompts/01_orchestration.md).
2. Partner prize choice, chain choice, scope cuts: decided by the team after reading the AI drafted event brief (docs/prompts/03_phase0_go.md).
3. Scope change to Bulkhead, an npm circuit breaker: product, safety rules, design rules, structure and phases written by the team (docs/prompts/bulkhead.md).

## Event brief

1. docs/event_brief.md: AI generated from the ETHGlobal Mumbai pages, read in the team's logged in browser. Team reviewed it and chose targets.
2. docs/rules.md: AI generated from the same pages, then updated with the team's decisions.

## Sluice, archived

1. Phase 0 of Sluice (root config, shared package, architecture, seven agent files, CLAUDE.md) was AI generated and reviewed by an AI reviewer agent. It is kept in git history under the tag sluice_archived.
2. On the scope change the AI removed the Sluice shared package, architecture and agent files from the working tree, on the team's instruction. No Sluice contracts, services or web code had been written.

## Bulkhead, Phase 0

1. docs/prompts/bulkhead.md: the team's prompt, saved word for word.
2. CLAUDE.md: AI generated. Style rules and slop list copied word for word from the team's prompt; product, safety and design rules condensed from docs/prompts/bulkhead.md.
3. README.md stub, package.json, pnpm-workspace.yaml, .npmrc, .gitignore, .env.example: AI generated. The workspace excludes demo/poisonedPackage and disables install scripts.
4. docs/rules.md: stack section updated by AI for the scope change.
5. packages/shared/src (constants, schemas, types, hashing, chain, abis/sealRegistry, hashing tests): AI generated.
6. docs/architecture.md: AI generated. Interface choices made by the AI and open for team review: nobody holds the admin role, so detectors and quorum are fixed per deployment; a vote that would exceed the daily seal limit reverts; votes on an Unsealed key revert so only the guardian can reseal; the watcher is the only timeline writer; demo quorum 2 of 3.
7. .claude/agents (contracts, detectors, watcher, guard, dashboard, research, reviewer, docs): AI generated from the team's agent list.
8. An AI reviewer agent audited Phase 0 and reported 24 findings. The AI applied 21 of them to the architecture, shared package, env, workspace, agent files and README. The AI applied them on its own judgment; the team has not reviewed them yet. Three that touch CLAUDE.md wait for the team.
9. After the team approved Phase 0: the AI edited CLAUDE.md (cut order, missing design rules, name exceptions), made replay timeline only in the shared schemas and architecture, and wrote docs/research/incidents.md on the TanStack incident. The team told it which sources to use and that the incident was verified; the AI found the links by web search.
10. Team decision on 6 Nov 2026: age fallback instead of fail open or closed, N placeholder 3, persistence and IDE or agent hook removal before token revocation. The AI applied it to CLAUDE.md, the architecture, the shared schemas, the guard agent file and the research note.

## Bulkhead, Phase 1

1. demo/poisonedPackage (v1.4.0, v1.4.1 with postinstall.js, pack.sh) and demo/canarySink (server.js, Dockerfile, package.json, canarySink.test.js): AI generated by the orchestrator. Benign by design: the postinstall only sends a fake token, and only to a local sink.
2. services/detectors/package.json, packages/guard/package.json and both tsconfig.json files: AI generated by the orchestrator so dependencies install once.
3. contracts/ (foundry.toml, foundry.lock, src/SealRegistry.sol, src/interfaces/ISealRegistry.sol, test/SealRegistry.t.sol, script/Deploy.s.sol, .gitmodules entries for OpenZeppelin v5.1.0 and forge std v1.9.4): AI generated by the contracts subagent. The SPDX license line at the top of each .sol file is kept because the compiler requires it.
4. services/detectors/src (staticScripts, sandboxCanary, advisoryFeed, signer, server, testSupport and their tests): AI generated by the detectors subagent.
5. services/detectors/src/fixtures (OSV responses for MAL-2026-3465, npm registry times for @tanstack/react-router): real responses recorded by the detectors subagent from api.osv.dev and registry.npmjs.org, not written by AI.
6. packages/guard (src: cli, sealedList, lockfile, check, audit, rollback, sidecar, registry, testFixtures and tests; bin/bulkhead.js): AI generated by the guard subagent.
7. docs/research (incidents, edge_cases, papers, replay_candidates): AI written by the research subagent from linked sources, each with an access date. The TanStack verification and the persistence instruction come from the team.
8. Shared schema changes in Phase 1 (snapshotAgeSeconds, nullable tooYoung publishedAt, scan failures, replay timeline, age fallback): AI generated by the orchestrator after the subagents raised them.
9. An AI reviewer agent audited Phase 1 and reported 25 findings. The subagents fixed their own packages and the orchestrator fixed the docs.

## Bulkhead, Phase 1 follow ups and Phase 2

1. Team decisions on 6 Nov 2026 (known lockfile formats only, git dependencies blocked by default with allow-git none where npm supports it, MAL ids only, audit of editor and coding agent hook files, runtime loaders, process logging, figures check, fitness and chaos tests): applied by the orchestrator to the architecture, shared schemas and env, then built by the subagents below.
2. packages/guard changes (lockfile formats and size limit, gitDependencies, allow-git gate at npm 11.9.0, hookFiles in audit): AI generated by the guard subagent.
3. services/detectors changes (runtime loaders, git dependencies, non JavaScript payloads as informational findings, sandbox process log through docker top): AI generated by the detectors subagent. The decision that shipped binaries alone never make a malicious verdict was made by the orchestrator to limit false seals.
4. docs/research changes (figures check with exact source sentences, git dependency mechanisms, allow-git, runtime loaders, CI token theft out of scope): AI written by the research subagent from linked sources. The fake npmrc mechanism stays marked not verified because its primary source could not be reached.
5. docs/limits.md: AI written by the docs subagent from the architecture and research notes.
6. tests/support/chain.ts and tests/fitness: AI generated by the orchestrator.
7. services/watcher (pollers, scheduler, timeline, publisher, reports, server, schema, tests): AI generated by the watcher subagent.
8. demo/mockRegistry, demo/services, demo/setup.sh, start.sh, stop.sh, env.sh, demo.env.example: AI generated by the demo subagent.
9. apps/dashboard (Next.js app, components, lib): AI generated by the dashboard subagent. Design choices (IBM Plex type pair, paper and ink palette with one accent) were made by that subagent following CLAUDE.md.
10. tests/chaos and tests/support/services.ts: AI generated by a chaos test subagent; it runs real anvil, watcher, detectors and guard processes and fakes only dead ports and stand ins for public services.
